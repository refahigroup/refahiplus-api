# وضعیت آمادگی کاتالوگ پس از پیاده‌سازی — 2026-11-02

**کد، تنظیمات قابل استقرار و gateهای بررسی پیاده شده‌اند؛ تأیید نهایی پروداکشن هنوز به تکمیل پوشش داده و بررسی روی سرور وابسته است.** تست بار طبق درخواست کاربر اجرا نشده و برای Stage به تعویق افتاده است.

این گزارش جایگزین نتیجه‌گیری قبلی درباره هشدار نتیجه ناقص و کلیدهاست: نمایش ندادن ناقصی، تصمیم محصول است؛ کلیدهای appsettings مربوط به Stage هستند. تعویض آن‌ها در این تغییر درخواست نشده و کلید نهایی روی سرور پروداکشن تزریق می‌شود.

## تغییرات انجام‌شده

| موضوع | نتیجه |
|---|---|
| کنترل ظرفیت API | policy مستقل CatalogueAdmission، هشت درخواست هم‌زمان، بدون صف، شانزده اجرای منبع؛ بودجه fan-out هنگام startup بررسی می‌شود |
| رد درخواست | 429 یکپارچه فارسی، Retry-After=1، no-store، شمارنده concurrency؛ callback ماژول‌های دیگر دست‌نخورده است |
| Nginx | سهمیه مشترک 20r/s برای هر socket IP، burst=40، بدون صف تأخیری؛ استثنای SSR فقط برای IP دقیق تأییدشده وب و فقط مسیر API |
| رفتار رابط | ناقصی در home search و SSR نمایش داده نمی‌شود؛ IsPartial و وضعیت منابع در API باقی مانده‌اند؛ 429 پیام امن و تلاش مجدد دستی دارد |
| وابستگی‌ها | OpenAPI=2.7.5، Pkcs/Xml=10.0.13؛ WebAssembly.Server نیز به‌دلیل هشدارهای یافت‌شده در audit وب به 10.0.13 رسید |
| تصاویر runtime | Dockerfileها runtime قدیمی‌تر از ASP.NET Core 10.0.13 را رد می‌کنند؛ pipeline نسخه و digest تصویر را ثبت می‌کند |
| پوشش داده | SQL و runner فقط‌خواندنی، تنظیمات JSON/environment، account جاری، وضعیت هر محدوده، JSON و جدول، خروج غیرصفر در حالت آماده‌نبودن |
| CI | اعتبارسنجی Merge Request، انتشار image فقط روی push شاخه‌های انتشار، audit اجباری، تست‌های مرتبط، دو fixture PostgreSQL بدون امکان skip، خروجی TRX/JUnit و gate پیش از Docker |
| مرورگر CI | job مستقل روی خروجی publish، Chromium، چهار ترکیب عرض و service worker؛ workflow قدیمی GitHub فقط بررسی دستی است |

کاتالوگ همچنان شامل hotels و entertainments است. مقدار پایه Catalogue:Enabled=false حفظ شده است. ماژول، route، render mode یا migration جدیدی اضافه نشده؛ شناسه‌ها، تاریخچه و مسیر Orders/Wallet تغییر نکرده‌اند.

## شواهد بررسی محلی

- build کامل Release بک‌اند: موفق؛ 11 warning و صفر خطا در اجرای نهایی.
- build کامل وب و publish نهایی Web با بسته اصلاح‌شده: موفق. publish لینوکس API نیز موفق است.
- 535 تست متمایز بک‌اند موفق: Catalogue=40، Hotels=146، Entertainments=138، Wallets=10، Orders=18، Flights=49، Store=106، SupplyChain=28.
- هر دو fixture تاریخی PostgreSQL هتل/تفریحات روی دیتابیس یک‌بارمصرف واقعاً پاس شدند؛ تست واقعی چرخه پرداخت Wallet هم با اتصال صریح مصرفی اجرا شد.
- کل solution فرانت‌اند: 229 تست متمایز موفق، شامل 22 تست Catalogue.
- 13 تست Node شامل service worker و 7 تست ابزارهای انتشار/guard گزارش موفق‌اند.
- 6 تست اختیاری بک‌اند Flights و 6 تست مرورگر Cinema در اجرای گسترده skip شده‌اند؛ هیچ‌کدام از دو fixture اجباری هتل/تفریحات skip نشده است. نام‌ها و نتیجه هر اجرا در TRX موجود است.
- audit گراف restore و gate وابستگی publish در هر دو مخزن موفق‌اند؛ backend audit شامل 103 پروژه است. هیچ هشدار امنیتی متوسط/بالا/بحرانی در audit نهایی گزارش نشد.
- Swagger کاتالوگ با نسخه‌های جدید کتابخانه در تست HTTP تولید شد.
- Nginx 1.28 روی Docker مصرفی: syntax، سهمیه مشترک، رد header جعلی، عبور 100 درخواست داخلی مورد اعتماد و عدم ثبت query/مختصات پاس شدند. در probe مربوط به پذیرش، 43 درخواست پذیرفته و 117 درخواست با 429 رد شدند؛ این تست ظرفیت‌سنجی Stage نیست.
- مرورگر روی خروجی publish، در 390px/1440px و service worker روشن/خاموش پاس شد: SSR بدون JS، هر دو منبع، جست‌وجو، province/city، nearby، تاریخچه، صفحه‌بندی، لغو نتیجه قدیمی، پاسخ ناقص بدون هشدار، نتیجه خالی، 429/503/timeout و نبود retry خودکار.

دانلود Chromium بسته‌بندی‌شده در این محیط پاسخ 403 مربوط به محدودیت جغرافیایی گرفت؛ بررسی محلی با Edge نصب‌شده انجام شد. پیش‌فرض اسکریپت و job لینوکسی CI، Chromium است و وابستگی اجباری به Edge حذف شده است.

بعضی اجراهای اولیه به‌علت کمبود حافظه/commit سیستم محلی و محدودیت بیش از حد heap ابزارها متوقف شدند. خروجی‌های موفق پس از تنظیم حافظه ابزار و اجرای مجدد ثبت شده‌اند؛ trimming یا بهینه‌سازی خروجی برای عبور از تست غیرفعال نشده است.

## پوشش فعلی داده محلی: آماده نیست

گزارش فقط‌خواندنی نهایی با تنظیمات مؤثر Local و دیتابیس همان محیط اجرا شد:

| منبع | محدوده بررسی | داده منتشرشده | مانع |
|---|---:|---:|---|
| SnappTrip | 316 نگاشت | 0 هتل | 182 محدوده missing_sync؛ فهرست خالی موفق در سایر محدوده‌ها به‌تنهایی خطا نیست |
| Lamasoo | 705 نگاشت فعال | 1621 هتل | یک محدوده sync_failed؛ داده آخرین موفقیت حفظ شده است |
| TouristPanel | account جاری | 81 خدمت | دو خدمت pending_details |

خروج بررسی ready=false است. این نتیجه به دیتابیس پروداکشن تعمیم داده نمی‌شود. هیچ timestamp، Status، Published یا IsPartial برای سبز شدن گزارش تغییر داده نشد؛ نگاشتی هم بدون بررسی مدیریتی غیرفعال نشد.

رفع موانع باید از مسیر worker، پاسخ/تنظیمات واقعی provider و مدیریت نگاشت موجود انجام شود. راهکار کدنویسی برای مخفی‌کردن این وضعیت اضافه نشده است. بررسی منابع HTTP و اطلاعات حساس provider در این گزارش منتشر نمی‌شود.

## موارد باقی‌مانده برای تأیید انتشار

1. تکمیل sync و جزئیات در همه محدوده‌های فعال محیط مقصد و عبور گزارش coverage، سپس smoke هر منبع و لینک جزئیات.
2. استخراج پیکربندی واقعی Nginx و IP دقیق وب روی سرور؛ اعمال snippetها، nginx -t و اطمینان از خصوصی بودن پورت API. تنظیمات این دستگاه جای تنظیمات سرور را نمی‌گیرند.
3. سرویس‌کردن image خصوصی runtime به حداقل نسخه لازم و بررسی digest/نسخه واقعی؛ image خصوصی روی این دستگاه موجود نبود و build آن روی registry سرور تأیید نشده است.
4. اجرای pipeline واقعی GitLab پس از ادغام؛ YAML و شکل دستورات محلی بررسی شده‌اند، ولی CI از این محیط trigger نشده است. نصب Chromium/runtime نیازمند دسترسی runner به منابع مربوط است.
5. دریافت واقعی metric/log در سامانه مانیتورینگ و مشاهده 24 ساعته پس از استقرار.
6. اجرای تست بار روی Stage در نوبت بعدی طبق تصمیم کاربر. اسکریپت و آستانه‌ها آماده‌اند؛ هیچ نتیجه عملکردی پروداکشن از unit test یا probe محلی استنتاج نشده است.

دستورالعمل عملی اجرا، نصب Nginx، گزارش coverage، شواهد CI و rollback در [راهنمای انتشار](catalogue-release-runbook.md) آمده است. شواهد محلی در artifacts/catalogue-release هر مخزن، و تصاویر مرورگر در artifacts/catalogue-search-qa مخزن وب قرار دارند. شواهد محلی working tree هستند و جای artifact متصل به commit/image نهایی CI را نمی‌گیرند.
