## تصمیم‌های اعمال‌شده

منبع این تصمیم‌ها پاسخ صریح کاربر در همین گفتگو است؛ تأیید مستقیم لاماسو محسوب نمی‌شوند. تصمیم بودروم و سیاست استان دبی نیز جداگانه تأیید شده‌اند. غلط املایی «انرونزی» به «اندونزی» اصلاح شده است.

| نام خام مقصد لاماسو | مقصد مرجع | استان مرجع | کشور | شناسه شهر مرجع |
|---|---|---|---|---:|
| رضوانشهر | رضوانشهر | گیلان | ایران | 1063 |
| استانبول | استانبول | ترکیه | ترکیه | 1335 |
| دوبی | دوبی؛ «دبی» همان مقصد است | امارات متحده عربی | امارات متحده عربی | 1336 |
| اسکله | اسکله | ترکیه | ترکیه | 1415 |
| `**` | ازمیر | ترکیه | ترکیه | 1322 |

| غیرفعال | بندر عسلویه | بوشهر | ایران | 327 |

پنج مقصد جدید ساخته می‌شود و پنج مورد از شهرهای موجود استفاده می‌کنند. بالی و لنکاوی `LocationKind=destination` دارند؛ شهر اداری بودن آن‌ها ادعا نمی‌شود. نام‌های خام مثل `**` و «غیرفعال» در نگاشت پرووایدر حفظ می‌شوند؛ نام مرجع، نام واقعی تأییدشده کاربر است.

طبقه‌بندی اسکله در کشور ترکیه، **تصمیم کاربر برای این مرجع تجاری** است. آدرس خام هتل لاماسو «Northern Cyprus» دارد؛ این مقدار و شناسه خام کشور/استان در Evidence حفظ شده‌اند. طبقه‌بندی کشور سایر مقصدهای قبرس تغییر نکرده است و GeoNames جعلی برای اسکله در ترکیه ساخته نشده است.

رکورد «غیرفعال» فقط از نظر هویت به عسلویه متصل می‌شود: ستون `hotels.lamaso_city_mappings.IsEnabled=false` برای آن است. شهر مرجع عسلویه غیرفعال نمی‌شود؛ سایر پرووایدرها نیز تغییری نمی‌کنند. مصرف‌کننده آینده نگاشت باید این فیلد را رعایت کند.

## یک استان واسط برای هر کشور خارجی

- ۳۱ استان واقعی ایران و ارجاع شهرهای ایران حفظ می‌شوند.
- برای هر کشور خارجی، دقیقاً یک استان همنام همان کشور با `IsSynthetic=true` نگهداری می‌شود. دبی هم استثنا نیست.
- برای کشورهای موجود، کوچک‌ترین شناسه استان خارجی موجود همان کشور استفاده می‌شود؛ استان واسط اندونزی با شناسه 61 اضافه می‌شود. `GeoNamesAdmin1Code` رکورد واسط خالی است، چون این رکورد استان واقعی نیست.
- ارجاع تمام شهرهای خارجی به استان واسط منتقل می‌شود؛ **شناسه و نام شهرهای V3 تغییر نمی‌کنند**. از شهرهای هم‌نام در یک کشور، بدون بررسی رکورد حذف نمی‌شود؛ برخورد نام پس از انتقال باعث توقف تراکنش می‌شود.
- ارجاع‌های FK به استان از کاتالوگ PostgreSQL کشف و منتقل می‌شوند. ستون‌های منطقی شناخته‌شده `identity.user_addresses.province_id`، `store.shops.ProvinceId` و `supplychain.suppliers.ProvinceId` نیز در صورت وجود منتقل می‌شوند. شناسه‌های native در درخواست هتل تغییر نمی‌کنند.
- تصویر کامل ۲۹ استان/ناحیه خارجی V3 در `"references".province_reorganization_history` باقی می‌ماند؛ ۱۳ شناسه به‌عنوان استان واسط بازاستفاده و ۱۶ رکورد اضافی حذف می‌شوند. ارجاع FK جدید به شناسه هدف تاریخچه است؛ BeforeImage رکورد قبلی را حفظ می‌کند.
- نگاشت استان‌های SnappTrip و لاماسو نیز به استان واسط هدایت می‌شود و BeforeImage نگاشت در Evidence می‌ماند. جدول‌های پرووایدر در schema `hotels` و با پیشوندهای `snapptrip_` و `lamaso_` هستند.

داده نهایی: **۱۵ کشور، ۴۵ استان/واسط، ۱۴۱۵ شهر/مقصد**؛ پوشش SnappTrip همچنان **۳۱۶ از ۳۱۸** و لاماسو **۷۰۶ از ۸۵۱** است. از ۷۰۶ نگاشت لاماسو، یک مورد هویتِ غیرفعال است؛ این عدد پوشش نگاشت است، نه تعداد مقصد فعال یا قابل خرید.

## موارد باقی‌مانده و فایل‌ها

هر ده مقصد دارای هتل در بررسی زنده نگاشت دارند. **۱۴۵ مقصد لاماسو باقی مانده‌اند که در همان بررسی API رکورد هتل نداشتند**؛ از مرجع یا صف بررسی حذف نشده‌اند. SQL داده احتمالی خارج از Snapshot را حدس نمی‌زند؛ تعارض شناسه، نام، کشور، FK یا نگاشت موجود باعث rollback می‌شود.

- `confirmed-mappings.csv`: ده تصمیم، شناسه مرجع، کشور/استان و فعال بودن نگاشت.
- `mapping-report.json`: تغییرات V4 نسبت به V3، شواهد هتل، تصمیم کاربر، شناسه‌ها، صف باقی‌مانده و هش منابع. این گزارش جایگزین گزارش کامل V3 نیست؛ تغییرات نسبت به آن را ثبت می‌کند.
- `remaining.csv`: صف ۱۴۵ مقصد باقی‌مانده.
- `validation.json`: نتیجه آزمون و SHA-256 فایل‌های اجرایی پس از آزمون.
- `../user-confirmed-destinations.json`: ورودی تصمیم‌های تأییدشده؛ `../build_mapping_v4.py` خروجی را بدون API یا اتصال دیتابیس بازتولید می‌کند.

## آزمون و محدوده اجرا

```powershell
python scripts/hotels/geography/build_mapping_v4.py
python -m unittest discover -s scripts/hotels/geography -p 'test_*.py'
python scripts/hotels/geography/verify_mapping_v4.py
```

آزمون یکپارچه فقط PostgreSQL 17 موقت در Docker، بدون شبکه و پورت منتشرشده می‌سازد و آن را حذف می‌کند. مسیرهای تازه، V1، V2، V3 و تکرار V4، ده نگاشت، حفظ شناسه شهرهای قبلی، استان واسط، تاریخچه، FK، ارجاع منطقی، غیرفعال ماندن نگاشت عسلویه و sequence بررسی می‌شوند. تعارض Snapshot، نام شهر پس از ادغام استان، نگاشت موجود و شناسه جدید باید بدون تغییر داده rollback شوند.

**روی دیتابیس عملیاتی اجرا نشده است.** C#، EF Migration، DTO و WebApp در این کار تغییر نکرده‌اند. فعال‌سازی مصرف این نگاشت‌ها و رسیدگی به لینک شناسه‌های قدیمی استان از طریق تاریخچه، کار جداگانه Runtime است. تنظیمات فعلی پرووایدر و امکان خرید تغییر نکرده‌اند.
